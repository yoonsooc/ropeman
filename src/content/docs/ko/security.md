Ropeman의 가장 중요한 설계 원칙은 한 문장으로 요약됩니다. **원본 소스 코드는 브라우저를 떠나지 않습니다.** 이 문서는 파일이 열리는 순간부터 다이어그램이 그려지기까지의 데이터 흐름을 단계별로 설명합니다.

## 핵심 원칙

- **로컬 파싱** — 파일은 브라우저의 File System Access API로 브라우저 안에서만 읽히고, 브라우저 내부 파서가 AST(추상 구문 트리)를 추출합니다. 이 과정에서 네트워크 요청은 발생하지 않습니다.
- **코드 구조 요약만 전송** — AI에는 AST에서 뽑은 **코드 구조 요약**만 보냅니다. 요약에는 파일 경로, 함수·클래스·메서드 이름, import가 들어갑니다. Markdown 파일은 frontmatter의 name과 description, 제목, 링크가 들어갑니다. 기본 한도는 **250 KB**입니다.
- **키는 로컬에만** — API 키는 브라우저에만 저장되며 Ropeman 서버에 저장되지 않습니다.

## 데이터 흐름 단계

1. **파일 접근** — 사용자가 폴더를 드롭하면 브라우저의 File System Access API를 통해 파일 핸들만 획득합니다. 파일 내용은 브라우저 메모리에만 존재합니다.
2. **AST 파싱** — 브라우저 내부 파서가 파일별로 AST를 만들고, 함수·클래스·임포트 같은 구조 정보만 추출합니다.
3. **코드 구조 요약 생성** — AST에서 위의 구조 정보만 모읍니다. 함수 본문, 주석, 문자열 리터럴, 변수 값은 넣지 않습니다.
4. **AI 호출** — 선택된 모드에 따라 코드 구조 요약만 LLM에 전송됩니다. 응답은 노드와 엣지의 목록이며 브라우저에서 즉시 렌더링됩니다.
5. **캐싱** — 결과는 브라우저 캐시에 저장돼 다음 세션에서 즉시 복원됩니다.

## 모드별 전송 경로

| 모드                          | 요약이 가는 곳                                              | Ropeman 서버 경유 |
| ----------------------------- | ----------------------------------------------------------- | ----------------- |
| **데모**                      | Ropeman 데모 Worker를 거쳐 Google Gemini API                | 예                |
| **API 키** (Gemini)           | 브라우저에서 Google Gemini API로 바로                       | 아니요            |
| **API 키** (Anthropic·OpenAI) | Ropeman 프록시 Worker와 Cloudflare AI Gateway를 거쳐 제공자 | 예                |
| **WebGPU**                    | 어디로도 가지 않습니다. 브라우저 안에서 추론합니다          | 아니요            |

- **데모** 요청은 Ropeman 데모 Worker로 가고, Worker가 Ropeman의 키로 Gemini 무료 등급을 호출합니다. 요청 횟수 제한을 위해 IP 주소별 요청 수를 메모리에서 세고, 요약과 응답은 저장하지 않습니다.
- **API 키** 모드에서 Gemini 키 요청은 브라우저에서 Google로 바로 가고, 키는 요청 URL에 담깁니다. Anthropic·OpenAI 키 요청은 브라우저 제약 때문에 Ropeman 프록시 Worker로 가고, 프록시가 Cloudflare AI Gateway를 거쳐 제공자에게 넘깁니다. 프록시는 요약, 응답, 키를 저장하지 않습니다. 제공자가 오류를 돌려주면 그 오류 응답은 로그에 남깁니다.
- **WebGPU** 모드는 모델을 내려받을 때만 네트워크를 씁니다. 그다음 분석은 오프라인에서 돕니다.

[ropeman.dev/bridge](https://ropeman.dev/bridge)의 브리지 모드는 이 세 모드와 별개입니다. 브리지 모드에서는 내 컴퓨터의 `ropeman serve`가 내가 연 폴더의 파일 경로, 선언된 심볼 이름, 파일 수와 import 수만 내 Claude Code나 Gemini CLI에 보내고, 파일 내용은 보내지 않습니다. CLI는 자기 로그인으로 제공자를 호출하고, 이 경로에 Ropeman 서버는 없습니다. 자세한 내용은 [브리지 설정](/docs/ko/bridge-setup)을 보세요.

## API 키 저장 및 처리

- API 키는 이 브라우저의 로컬 저장소에 제공자별로 하나씩 저장됩니다. Ropeman 서버는 키를 저장하지 않습니다.
- Gemini 키는 브라우저에서 Google로 바로 가고, Ropeman 서버에 닿지 않습니다.
- Anthropic·OpenAI 키는 요청마다 Ropeman 프록시로 함께 갑니다. 프록시는 그 요청 하나에만 키를 제공자 인증 헤더에 넣고, 아무것도 남기지 않습니다.
- **설정 → 초기화** 버튼이나 브라우저의 사이트 데이터 삭제로 언제든 지울 수 있습니다.
- 공유 PC나 타인의 브라우저에서 Ropeman을 쓸 때는 작업 종료 후 반드시 키를 삭제하시기 바랍니다.

## 개인정보 처리 원칙

- **최소 수집** — 회원가입이 없으며, 사용자 식별 정보를 수집하지 않습니다.
- **요약과 다이어그램 비보관** — 데모 Worker와 프록시는 요청 본문을 저장하지 않습니다. 남는 로그는 Cloudflare Workers의 요청 기록과, 제공자가 돌려준 오류 응답입니다. 공유 링크를 만들면 링크가 열리도록 다이어그램, 프로젝트 이름, 파일 경로를 14일 동안 저장합니다.
- **제3자 공유 없음** — 코드 구조 요약은 선택한 모드의 AI 제공자에게만 갑니다. Anthropic·OpenAI 요청은 그 길에 Cloudflare AI Gateway를 거칩니다.
- **분석 도구** — 웹사이트 이용 통계는 쿠키와 지문 수집이 없는 익명 집계 도구로만 수집합니다.

더 자세한 모드 비교는 [AI 모드 가이드](/docs/ko/ai-modes)를 참고하세요.
