# W1: retrieval baseline on SWE-QA (requests, flask)

Which retrieval strategy finds the files a reference answer relies on, when the index
holds only code structure (symbols, signatures, docstrings, imports) and no function bodies?

## Setup

| item             | value                                                                                                                |
| ---------------- | -------------------------------------------------------------------------------------------------------------------- |
| questions        | SWE-QA `requests.jsonl` + `flask.jsonl`, 96 total, **95 scored** (1 answer names no file)                            |
| benchmark source | [peng-weihan/SWE-QA-Bench](https://github.com/peng-weihan/SWE-QA-Bench) @ `c13deac`, Apache-2.0                      |
| repos            | psf/requests @ `46e939b` (675 chunks), pallets/flask @ `85c5d93` (from `repo_commit.txt`)                            |
| gold files       | `*.py` paths named in the reference answer, resolved to exactly one indexed file (`eval/swe_qa.py`)                  |
| strategies       | BM25 (rank-bm25 Okapi, code-aware tokenizer), vector (pgvector exact cosine), hybrid (RRF, k=60, 20 candidates each) |
| embedding        | `jinaai/jina-embeddings-v2-base-code`, 768-d, local ONNX via fastembed, input clipped to 2,000 chars                 |
| retrieval depth  | 10 chunks; Recall@5 and Hit@5 use the first 5                                                                        |
| statistics       | paired bootstrap over questions, 10,000 resamples, seed 0                                                            |
| LLM              | not used (retrieval only)                                                                                            |

Reproduce: `uv run python -m eval.swe_qa && uv run python -m eval.run` (≈50 s on a laptop after indexing).
Per-question output: `eval/results/W1.jsonl`.

## Metrics

- **Recall@5**: share of a question's gold files that appear among the top-5 chunks.
- **Hit@5**: 1 if at least one gold file is in the top 5.
- **MRR@10**: mean of 1 / rank of the first chunk from a gold file (0 if none in the top 10).

## Results

| strategy | Recall@5 flask | Recall@5 requests | Recall@5 all | Hit@5 all | MRR@10 all | p50 latency |
| -------- | -------------- | ----------------- | ------------ | --------- | ---------- | ----------- |
| bm25     | 0.722          | 0.647             | 0.685        | 0.916     | 0.806      | 1 ms        |
| vector   | 0.674          | 0.693             | 0.683        | **0.958** | **0.882**  | 17 ms       |
| hybrid   | 0.648          | 0.675             | 0.661        | 0.916     | 0.862      | 18 ms       |

| pair (a − b)    | metric   | mean diff | 95% CI           | CI excludes 0 |
| --------------- | -------- | --------- | ---------------- | ------------- |
| bm25 − vector   | Recall@5 | +0.002    | [−0.058, +0.058] | no            |
| bm25 − vector   | MRR@10   | −0.076    | [−0.149, −0.006] | **yes**       |
| bm25 − hybrid   | Recall@5 | +0.024    | [−0.029, +0.078] | no            |
| bm25 − hybrid   | MRR@10   | −0.056    | [−0.104, −0.011] | **yes**       |
| vector − hybrid | Recall@5 | +0.022    | [−0.025, +0.073] | no            |
| vector − hybrid | MRR@10   | +0.020    | [−0.028, +0.069] | no            |

## What this says

1. **Coverage is a tie.** Recall@5 differs by at most 0.024 between strategies, and every
   interval spans 0. With 95 questions the data cannot separate the three on how many gold
   files reach the top 5.
2. **Ranking is not.** Vector and hybrid put the first relevant file higher than BM25
   (MRR +0.076 and +0.056, both intervals above 0). Per question, vector beats BM25 on 20,
   loses on 10, ties on 65.
3. **Hybrid did not beat vector alone.** RRF lands between its two inputs on MRR and is
   lowest on Recall@5. On these questions BM25's extra candidates mostly push down
   chunks that vector had ranked well. "Hybrid wins by default" does not hold here.
4. **Identifiers help every strategy.** Questions that name an identifier (backticks,
   snake_case or CamelCase; 43 of 95) score MRR 0.86–0.91. The other 52 score 0.77–0.86.
   BM25 loses the most when the question names none.

## Failure cases (Hit@5 = 0 for all three strategies: 3 questions)

| id          | what went wrong                                                                                                                                                                            | category                |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------- |
| requests-03 | Asks about `InvalidSchema`'s inheritance. All strategies return `exceptions.py`, where the class is defined, but the answer only names `sessions.py` and `adapters.py`, where it is raised | gold label incomplete   |
| requests-36 | Asks about the test `test_transfer_enc_removal_on_redirect`. Retrieval returns `tests/test_requests.py`, which the answer never names                                                      | gold label incomplete   |
| requests-27 | Asks about `_body_position`, an attribute assigned inside method bodies (`models.py`, `sessions.py`). The skeleton index has no bodies, so nothing mentions it                             | **skeleton-only limit** |

Two of the three "misses" are labelling artefacts: gold files come from the paths an answer
happens to mention, which can leave out the defining file. The third is a real cost of
indexing structure only, and it is the kind of question to count when measuring that cost
against a full-source index.

## Limits

- **Two repos, both well known.** The embedding model and SWE-QA's answer writers may
  have seen this code in training. Results may not carry over to private code.
- **File-level gold only.** A hit on the right file but the wrong symbol still counts.
- **Gold comes from mentioned paths**, so recall is measured against what the answer names,
  not against everything that is relevant (see failure cases).
- **One embedding model.** A paid model (e.g. gemini-embedding-001) has not been run on the
  same questions yet. The code supports it with `EMBEDDING_PROVIDER=gemini` and a separate
  table, so the comparison is a re-index plus a re-run.
