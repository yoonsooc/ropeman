# Public Gallery (`/explore`) Refresh Guide

The `/explore` gallery shows AI-generated architecture snapshots of curated
open-source projects (React, Vue, Svelte, FastAPI, Gin, …). Per
[ADR-19](../docs/adr/0019-explore-manual-refresh.md), these snapshots are **manually refreshed** rather
than auto-generated by a Cloudflare Cron — refreshing them is a 5–15 minute
job done a few times a year.

## One-time setup

1. Create the KV namespace:

   ```sh
   cd edge-proxy
   wrangler kv namespace create ROPEMAN_EXPLORE_STORE -c wrangler.explore.toml
   ```

   Paste the returned `id` into `wrangler.explore.toml` (replace `REPLACE_WITH_KV_ID`).

2. Set the admin token (used for `POST` / `DELETE`):

   ```sh
   # Generate a random token, then:
   wrangler secret put EXPLORE_ADMIN_TOKEN -c wrangler.explore.toml
   ```

3. Deploy the worker:

   ```sh
   npm run deploy:explore
   # or from repo root: npm run deploy:edge:explore
   ```

4. Verify:
   ```sh
   curl https://explore.ropeman.dev/explore   # → { "slugs": [] }
   ```

## Refreshing a snapshot

Snapshots are built the way a user of the Ropeman skill maps a repo, by
`scripts/explore/pipeline.mjs` (see `docs/ARCH.md`, "갤러리 스냅샷 파이프라인").
`scripts/explore/repos.json` pins each slug to a repository, a commit and a
batch. Needs Node 22+, git and a logged-in `claude` CLI.

1. **Pin the commit**: set the slug's `commit` in `scripts/explore/repos.json`
   (`git ls-remote https://github.com/<owner>/<repo> HEAD`).

2. **Build** (minutes per repository; reruns skip finished steps):

   ```sh
   node scripts/explore/pipeline.mjs react        # one slug
   node scripts/explore/pipeline.mjs --batch 1    # every slug of a batch
   ```

   The mapping agent runs in a sandbox (`scripts/explore/agent.mjs`): it reads
   only the clone and its output folder, writes only the output folder, and its
   `ropeman` runs only `map`/`verify` on those two folders. After changing the
   sandbox, run `node scripts/explore/probe-sandbox.mjs` (about $0.10); it tries
   each escape from a hostile repository and exits 1 if one gets through.

   Each `~/.cache/ropeman-explore/<slug>/` then holds `snapshot.json` and
   `report.json` (cost, time, size, the checks). The checks fail a snapshot
   whose public text holds a home or system path or something shaped like a
   secret (private key, AWS key id, GitHub or API token, JWT). The snapshot records the
   analyzed `commit`, repository paths, and Korean names in `translations.ko`.

3. **Check, then upload** from your own terminal:

   ```sh
   node scripts/explore/upload.mjs --batch 1 --dry-run     # sizes and hashes, no token
   EXPLORE_ADMIN_TOKEN=... node scripts/explore/upload.mjs --batch 1   # or name slugs
   ```

   With neither slugs nor `--batch` it takes every built snapshot. It refuses a snapshot whose
   checks failed, that changed after the build, or that is not from the pinned
   commit, then reads each one back and compares its sha256. It stops at the
   first 401, and `--url` must be https (or `http://localhost` for a local
   worker). The token is read
   from the environment only and never printed. The worker accepts up to 16 MiB
   per snapshot and stores the uploaded text byte for byte.

4. **Verify** at https://ropeman.dev/explore/react in English and Korean, then
   open a file from a node's panel.

Snapshots uploaded before `commit` existed fall back to the entry's `ref` in
`src/lib/data/explore-curated.json`. Once a slug's new snapshot is uploaded,
its `ref` can be deleted.

## Adding a new curated entry

1. Edit `src/lib/data/explore-curated.json` and append a new object:
   ```json
   {
   	"slug": "django",
   	"owner": "django",
   	"repo": "django",
   	"title": "Django",
   	"language": "Python",
   	"description": "The web framework for perfectionists with deadlines.",
   	"stars": "82k+"
   }
   ```
2. Add the slug to `scripts/explore/repos.json` with the same owner and repo
   (a unit test checks they agree), and update `updatedAt` to today.
3. Run `npm run build` — the new slug is auto-included in the prerendered
   `/explore/[slug]` route via `entries()` and added to `sitemap.xml`.
4. Refresh the snapshot following the steps above.

## Removing an entry

1. Delete the entry from `src/lib/data/explore-curated.json`.
2. Delete the KV entry:
   ```sh
   curl -X DELETE https://explore.ropeman.dev/explore/<slug> \
     -H "Authorization: Bearer $EXPLORE_ADMIN_TOKEN"
   ```
3. Rebuild & redeploy.

## Cost & limits

- KV reads are free (cached at the edge); each fetch is `Cache-Control: public, max-age=300, s-maxage=3600`.
- KV storage is ~$0.50/GB/month — ten snapshots of up to a few MB cost essentially $0.
- The admin token is the only thing standing between malicious uploads and KV;
  rotate it if it leaks: `wrangler secret put EXPLORE_ADMIN_TOKEN -c wrangler.explore.toml`.

## CORS policy note

The explore worker's `ALLOWED_ORIGINS` allowlist applies **only when the
request has an `Origin` header** — i.e. when a browser is calling from
another site. Server-to-server callers (curl, CI, admin scripts) do not
send `Origin`, so the allowlist is skipped for them and the request
proceeds straight to routing. For admin `POST` / `DELETE`, the Bearer
token is the real authorization check; the `Origin` allowlist only
guards browser traffic that would otherwise bypass CORS. This means
the `curl` examples above work without needing `-H "Origin: ..."`.
