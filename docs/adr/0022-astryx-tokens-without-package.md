# ADR-22: astryx 디자인 토큰과 규칙만 가져오고 패키지는 쓰지 않는다

- **날짜**: 2026-11-12
- **문제**: 스타일 블록에는 간격·반경·글자 크기·그림자·포커스 토큰이 하나도 없었다. 간격 711곳, 반경 200곳, 글자 크기 368곳이 숫자를 직접 썼다. 색 토큰은 이름 체계가 `--bg-*`, `--accent-*`, `--ghost-*`로 섞여 있었고, 19개는 아무도 쓰지 않았다. 라이트 모드의 오류·경고·성공 글자는 대비가 1.97~3.45:1이라 WCAG AA 하한(일반 글자 4.5:1)에 모두 못 미쳤다. `:focus-visible` 규칙은 2개뿐이었고 `outline: none`이 10곳이라, 키보드 포커스 모양이 요소마다 달랐다. 디자인 시스템의 기준으로 astryx(`github.com/meta/astryx`, MIT)를 쓰기로 한 상태에서, 무엇을 어떤 방식으로 가져올지 정해야 했다.
- **검토 대안**:
  - (A) astryx 컴포넌트와 테마 패키지를 설치해 쓴다. 값이 자동으로 따라온다. 하지만 컴포넌트는 React 19와 StyleX로 만들어졌고 Ropeman은 Svelte 5다.
  - (B) 테마 패키지(`@astryxdesign/theme-neutral`)만 설치하고 `dist/theme.css`를 불러온다. 값은 업데이트로 따라온다. 하지만 테마 패키지도 React 19를 peer 의존성으로 요구하고 `lucide-react`를 끌어온다. 모드 전환도 `@scope`, `@layer`, `data-astryx-theme`, `light-dark()` 방식이라, `[data-theme]` 속성 하나로 모드를 바꾸는 Ropeman(explore·share 페이지는 자기 루트에도 단다)과 맞지 않는다.
  - (C) 토큰 이름 문법, 척도, 규칙, 일부 값만 손으로 옮긴다. 패키지는 설치하지 않는다. 값이 바뀌면 사람이 다시 비교해야 한다.
  - 기준 테마는 무채색 계열 두 개를 비교했다.
    - Neutral: 순수 회색 표면, 채도가 분명한 상태 색(라이트 오류 글자 `#c0262c`), 대비 하한을 스펙과 테스트로 묶은 기준 구현이다. 반경은 6·10·12·28px이다.
    - Stone: 보랏빛 회색 표면, 갈색·올리브 톤의 상태 색, 라이트 비활성 글자 1.31:1이다. 반경은 4·8·12·24px이다.
  - 값마다 둔 선택지는 아래와 같다.
    - 표면: 라이트만 Neutral의 가까운 스톱(램프 21단계 중 한 단계)으로 맞추기, 또는 두 모드 모두 Neutral 값 그대로 쓰기.
    - 상태 색: 두 모드 모두 Neutral 역할과 값으로 바꾸기, 또는 라이트만 바꾸기.
    - 강조색: 지금 값(라이트 `#1d4ed8`, 다크 `#a3a6ff`) 유지, Neutral 흑백 강조(`#1b1b1b` / `#f1f1f1`), astryx 파랑 램프(`#0067ce` / `#a1caff`).
    - 글자 크기: astryx 14px 기준 척도, 또는 지금 크기(13·11px 포함)에 역할 이름만 붙이기.
    - 간격 단위: rem, 또는 px.
    - 반경: Neutral 6·10·12px, 또는 astryx core 기본값 4·8·12px.
- **결정**: C, 기준 테마는 Neutral이다. 값은 `@astryxdesign/theme-neutral@0.7.13`의 `dist/theme.css`에서 읽었다. 값의 결정은 사용자가 2026-11-12에 확정했다.
  - 색 토큰은 astryx 역할 문법으로 이름을 바꿨다(`--color-background-surface`, `--color-text-secondary`, `--color-on-accent` 등). 옛 이름은 별칭 없이 같은 변경에서 지웠고, 쓰이지 않던 19개도 지웠다.
  - 라이트 표면은 Neutral의 가까운 스톱으로 옮겼다. 밝기 변화는 L\*(사람이 느끼는 밝기, 0~100) 약 2 이하이고, 팝오버만 회색에서 흰색이 됐다. 다크 표면은 2026-11-09에 대비를 맞춘 Ropeman 값을 그대로 두고 이름만 바꿨다.
  - 상태 색은 두 모드 모두 Neutral 값이다. 쓰이는 표면마다 역할을 나눴다. 페이지 위 글자 `--color-text-*`, 진한 채움 `--color-*`과 그 위 글자 `--color-on-*`, 옅은 채움 `--color-*-muted`와 그 위 글자 `--color-on-*-muted`, 점·아이콘 `--color-icon-*`, 테두리 `--color-border-*`다.
  - 강조색은 라이트 `#1d4ed8`, 다크 `#a3a6ff`를 유지했다.
  - 노드 종류(`--color-directory` 등), AI 트랙(`--track-*`), 엣지 범례(`--color-edge-*`)는 Ropeman 고유 범주 색이라 이름을 유지했다. 라이트 값 일부는 흰 바탕에서 3:1을 넘도록 바꿨다.
  - 글자 크기는 14px(`--font-size-base`)을 기준으로 한 rem 척도(10·12·14·17·20·24·29·35px)다. 13px은 14px로, 11px은 12px로 옮겼다. 줄 간격은 토큰으로 묶지 않았다.
  - 간격은 4px 격자의 rem 토큰(`--spacing-N` = N × 0.25rem)이다. 그래프 노드 내부(`src/lib/components/nodes/`, xyflow 노드·엣지 규칙)는 dagre가 px로 배치하므로 px로 둔다.
  - 반경은 core 기본값 4·8·12px을 역할로 고른다. `--radius-inner`(배지·kbd), `--radius-element`(버튼·입력란), `--radius-container`(카드·모달), `--radius-full`이다.
  - 포커스 링은 전역 `:focus-visible` 규칙 하나가 `--focus-outline-width`(2px), `-style`(solid), `-color`(강조색), `-offset`(3px)으로 그린다. 넘친 부분을 자르는 컨테이너 안에서는 요소에 `--focus-outline-offset: -2px`를 준다.
  - 그림자는 `--shadow-low`·`med`·`high` 3단계, 동작은 `--duration-fast`(125ms)·`--duration-medium`(300ms)과 `--ease-standard`다.
  - 규칙이 지켜지는지는 `src/lib/styles/tokens.test.ts`가 검사한다. 두 모드의 WCAG AA 대비 하한, 정의되지 않은 `var()` 참조, 쓰이지 않는 전역 토큰, 스타일 블록 안의 색 리터럴, 척도 토큰 대신 쓴 px·rem 글자 크기와 반경이다. 그래프 선과 화살촉이 범례와 같은 `--color-edge-*` 토큰을 쓰는지도 본다.
  - 출처 표기는 MIT를 따른다. `src/lib/styles/global.css` 머리 주석에 astryx 0.7.13과 저작권자를 적고, `LICENSES/astryx-MIT.txt`에 라이선스 전문을 뒀다.
- **기각 이유**:
  - A는 Svelte 앱에 React 런타임을 들여야 한다. 컴포넌트를 쓰지 않으면 설치할 이유가 없다.
  - B는 쓰지도 않을 React 19와 `lucide-react`를 의존성으로 끌어오고, 모드 전환 방식을 `[data-theme]`에서 바꿔도 얻는 것이 없다. 값을 업데이트로 받는 장점도, Ropeman이 다크 표면과 강조색을 따로 정하는 이상 덮어쓸 값만 늘어난다.
  - Stone은 상태 색의 채도가 낮아 코드 도구에서 오류와 경고를 빨리 구분하기 어렵고, 비활성 글자가 거의 보이지 않는다.
  - 두 모드 모두 Neutral 표면을 쓰면 라이트는 셸과 패널의 밝기가 뒤집히고(셸이 회색 `#f1f1f1`, 패널이 흰색), 다크는 전체가 밝아진다(셸 `#0b0c0e` → `#1b1b1b`). 다크 Neutral 램프는 단계 사이 간격이 Ropeman 단계보다 넓다.
  - 다크 상태 색을 그대로 두면 다크도 대비는 통과하지만, 두 모드의 역할 체계가 달라진다.
  - Neutral 흑백 강조는 그래프에서 선택과 연결선을 강조할 색상이 없다. astryx 파랑 램프는 이미 대비를 맞춘 지금 값보다 나은 점이 없다.
  - 지금 글자 크기를 유지하면 Ropeman만의 13·11px이 척도에 남아, 비슷한 크기를 임의로 고르는 문제가 그대로다.
  - px 간격은 브라우저 글자 크기를 키운 사용자에게 간격이 같이 커지지 않는다.
  - Neutral 반경 6·10px은 지금 가장 많이 쓰는 4·8px(반경 선언 200개 중 88개)을 거의 다 바꿔야 한다.
  - 함께 가져오지 않은 것도 있다. Figtree 글꼴은 글꼴을 하나 더 내려받게 하고 Inter·Space Grotesk 정체성을 바꾼다. astryx 본문 줄 간격 1.4286은 한글 여러 줄 문단에 좁다. `--color-syntax-*`는 사용자가 고르는 Prism 테마가 정한다(ADR-7). `--color-data-categorical-*`는 두 모드에 같은 값을 써서 다크 셸에서 보라가 3.01:1이다. duration 변형과 dynamic type 변수는 React 런타임용이다.
- **결과**:
  - `package.json`과 lockfile은 바뀌지 않았다.
  - 색 단계(#48): 이름 변경 799곳, 대체값 제거 138곳, 49개 파일. 스타일 블록의 색 리터럴은 120곳에서 0곳이 됐다. 토큰 값으로 계산한 대비(WCAG 2.x 공식, 반투명 색은 셸 위에 합성, 브라우저 측정 아님)에서 하한 미달 쌍이 17개에서 0개가 됐다. 라이트 오류 글자는 3.45에서 5.23:1, 경고 글자는 1.97에서 4.76:1이 됐다. 키보드 Tab 62곳에서 링이 모두 `solid 2px` 강조색이었고 잘린 링은 0개였다.
  - 척도 단계(#52): 다시 돌릴 수 있는 변환 스크립트가 46개 파일의 스타일 블록만 바꿨다. 패널 글자가 1px 커지고, 10·14px이던 안쪽 여백이 2px 줄었다. 1440px·390px에서 새로 잘리거나 가로 스크롤이 생긴 곳은 없었다. 그래프 첫 화면 스크린샷은 픽셀 0.2%가 달랐고 툴바와 경로 표시줄에만 있었다. hover 전환이 150~200ms에서 125ms로 빨라졌다.
  - `tokens.test.ts`에 일부러 틀린 값(대비 미달 성공 색, 정의되지 않은 `var()`, 색 리터럴 `#fff`)을 하나씩 넣으면 그 항목 하나로 실패하고, 되돌리면 통과하는 것을 확인했다.
- **재검토 조건**: npm에 astryx 0.7.14 이후 정식판이 나오면 Neutral 값이 바뀌었는지 다시 비교한다. Ropeman이 React로 옮기면 B나 A를 다시 본다. 다크 표면이나 강조색에서 대비 미달이 나오면 Neutral 값으로 옮기는 안을 다시 본다. 한글 줄 간격을 바꿔야 할 근거가 생기면 줄 간격 토큰을 다시 본다. 모바일 작업을 시작하면 터치 화면에서 글자 기준을 16px로 키우는 astryx 규칙을 다시 본다.
