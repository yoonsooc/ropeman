# ADR-24: `ropeman.json` 형식과 버전, Bridge RPC가 같은 타입을 쓴다

- **날짜**: 2026-11-12
- **문제**: 2단계에서는 지도를 브라우저 밖에서 만든다. 스킬과 CLI가 지도를 만들고, 뷰어는 그 지도를 두 길로 받는다. 하나는 ropeman.dev의 "JSON 열기"로 여는 `ropeman.json` 파일이고(오프라인·공유용, ADR-23), 다른 하나는 Bridge 소켓의 RPC 메시지다. 지금까지 앱 밖으로 나간 지도 형식은 공유·갤러리 스냅샷(`semanticLevels` 객체)뿐이었고, 버전이 없었다. 두 길 모두 다른 사람이 보낸 파일이나 로컬 소켓에서 오므로 믿을 수 없는 입력이다. 또 사이트와 사용자 기기의 CLI는 따로 갱신되니, 버전이 다른 두 쪽이 만나도 서로 읽을 수 있어야 한다.
- **검토 대안**:
  - 형식
    - (A) 공유 스냅샷 모양(`Record<string, SemanticLevel>`)을 그대로 파일로 쓴다. 공유·갤러리 뷰어를 그대로 쓴다. 하지만 버전이 없고, 노드 색과 깊이 같은 화면 값까지 파일에 들어간다. 앱 내부 타입을 바꾸면 파일 형식도 같이 바뀐다.
    - (B) 코드 지도(`CodeMap`) 전체를 직렬화한다. 심볼 트리, import·참조 위치, 후보 대상까지 담는다. 하지만 `SymbolId`의 `~n`은 그 지도 안에서만 유효하고(ADR-21), 지금 뷰어에도 T2-3 검증기에도 이 값을 읽는 쪽이 없다.
    - (C) 파일 전용 타입을 두되 필드는 기존 타입에서 가져온다. 행방은 `FileCoverage`, 관계 근거는 `EdgeEvidence`, 배정 수는 `AssignmentCounts`, 노드 필드는 `SemanticNode`에서 가져온다. 뷰어가 계산하는 값(색, 깊이, 부모, 파일 수)은 넣지 않는다.
  - 버전
    - (1) 정수 하나(`version: 1`). 다르면 거부한다. 필드 하나만 더해도 버전이 바뀌므로, CLI가 먼저 갱신되면 사이트가 그 파일을 못 연다.
    - (2) semver 문자열 전체. patch에 해당하는 변경이 형식에는 없다.
    - (3) `MAJOR.MINOR`. 읽는 쪽은 자기 major의 모든 minor를 읽고 모르는 필드는 버린다.
  - 닫힌 값 목록(행방 이유, 관계 종류, 단계 이름 상태)에 값을 더하는 경우
    - (i) minor로 허용하고, 모르는 값은 버리거나 `unknown`으로 읽는다.
    - (ii) major를 올린다.
  - 타입을 둘 곳
    - (a) `bridge/src`에 두고 앱이 가져온다. 형식이 Bridge 구현에 묶인다.
    - (b) `src/lib/types/`에 두고, bridge의 tsconfig `rootDir`를 저장소 루트로 넓혀 같은 파일을 컴파일한다.
    - (c) 별도 패키지로 뺀다.
  - 검사: zod 같은 스키마 라이브러리, 또는 직접 쓴 파서.
  - `map.changed`: 바뀐 지도 전체를 푸시하거나, 바뀐 경로만 알리고 뷰어가 `map.get`을 다시 부르게 한다.
- **결정**: 형식 C, 버전 3, 닫힌 값 추가는 ii, 위치 b, 직접 쓴 파서, `map.changed`는 경로만 알린다.
  - 파일은 `format: "ropeman-map"`, `schemaVersion`, 프로젝트 이름, 만든 도구(`generator`)와 시각, `files`, `levels`를 담는다. 경로는 모두 저장소 기준이다. 단계(`MapLevel`)마다 `naming`이 있다. `grouped`는 CLI가 폴더로 바로 묶은 결정론 결과이고, `named`는 LLM이 붙인 이름이 결정론 검사를 통과한 결과다(A-12).
  - 읽는 쪽은 자기 major만 읽는다. minor는 선택 필드만 더한다. 필수 필드 추가, 필드 삭제, 닫힌 목록의 값 추가는 major다. 오래된 뷰어가 모르는 행방 이유를 짐작해 읽으면, 건너뛴 파일을 보낸 파일로 세는 식의 틀린 보고가 나오기 때문이다. RPC 오류 코드만 열린 목록이다. 모르는 코드는 `unknown`으로 읽고, 함께 온 문장(`error`)을 보여 준다. 그래서 새 CLI는 major를 올리지 않고 오류 코드를 더할 수 있다. `node.named` 푸시의 코드(`queued`처럼 ADR-25가 더한 것)도 이 열린 목록이다. 파서가 모르는 코드를 `unknown`으로 읽으므로 닫힌 목록의 major 규칙에 들지 않는다.
  - 파서(`services/ropemanMapSchema.ts`)는 크기(16MiB, Bridge `maxPayload`와 같은 값), JSON, `format`, 버전, 구조 순서로 본다. 버전은 구조보다 먼저 본다. 그래야 구조가 달라진 새 major 파일도 "더 새로운 Ropeman이 만든 지도"로 거부된다. 구조 오류는 틀린 필드 위치(`levels[1].nodes[0].label`)와 함께 돌려준다. 단계는 트리여야 한다. 노드 id는 지도 전체에서 하나뿐이고, 최상위 단계도 하나다. 나머지 단계는 최상위에서 닿는 노드를 하나씩 펼친다. 값은 필드마다 새 객체로 복사하므로 모르는 필드와 상속된 키가 앱으로 들어오지 않는다. 색처럼 화면 스타일이 되는 값은 파일에서 받지 않는다.
  - RPC는 요청 `{ id, type }`에 응답 `{ id, type, result }` 또는 `{ id, type, code, error }`다. `map.get`은 `RopemanMap`을 돌려준다. `node.expand`는 노드 id를 받아 `grouped` 단계를 바로 돌려주고, 검증이 끝나면 `node.named` 푸시를 보낸다(성공이면 `named` 단계, 실패면 코드와 문장). 이미 이름이 붙은 노드는 `named` 단계를 바로 돌려주고 푸시를 보내지 않는다. `file.read`는 #72에서 낸 모양을 그대로 쓴다. 바뀐 점은 내부 오류에도 `code: "internal"`을 붙인 것 하나다. 서버는 연결마다 `hello`로 스키마 버전을 먼저 보내고, 뷰어는 major가 다르면 거부한다. 서버 구현은 T2-4가 한다.
  - `types/ropemanMap.ts`는 타입만 import한다. bridge는 `rootDir`를 넓혀 이 파일을 그대로 컴파일하고, `file.read`의 `FileContent`와 거부 코드를 여기서 가져온다. 그래서 빌드 결과의 bin 경로가 `dist/bridge/src/server.js`로 바뀌었다. T2-2의 Node 코어는 `$lib` 별칭을 푸는 Vite SSR 번들로 같은 파일을 읽는다. (2026-11-13, T2-4: bridge도 코어처럼 Vite SSR 번들 `dist/server.mjs` 하나로 빌드한다. 파서와 검증기를 런타임에 부르게 되어 `$lib` 별칭을 풀어야 했기 때문이다. `ropeman serve`가 이 RPC의 서버 구현이다.)
  - ropeman.dev에는 `/open`을 두었다. 랜딩의 "ropeman.json 열기" 링크로 들어가 파일을 고르거나 끌어다 놓는다. 열린 지도는 공유 뷰어와 같은 스냅샷 모드로 보이고, 파일에 없는 단계는 AI를 부르지 않는다. 거부된 파일은 이유와 "다른 파일 열기" 버튼을 보여 준다.
- **기각 이유**:
  - A는 버전을 붙일 곳이 없고 화면 값이 형식이 된다. 공유·갤러리 스냅샷은 그대로 두고, 이 형식으로 옮길지는 따로 정한다.
  - B는 읽는 쪽이 없는 큰 구조를 지금 약속하게 된다. 심볼과 코드 관계가 필요해지면 선택 필드(`symbols`, `relations`)로 minor에서 더한다.
  - 1은 필드 하나만 더해도 사이트와 CLI가 서로 못 읽는다. 2의 patch는 쓸 일이 없다.
  - i는 오래된 뷰어가 모르는 값을 짐작하게 된다. 행방이나 관계 종류를 짐작하면 보고가 틀린다.
  - a는 형식이 Bridge 구현에 묶이고, c는 지금 쓰는 쪽(앱, bridge, T2-2 코어)이 모두 이 저장소 안이라 너무 이르다.
  - 스키마 라이브러리는 주요 의존성 추가라 사용자 결정이 필요하다. 이 형식의 검사는 필드 위치 보고와 트리 검사까지 파일 하나(약 430줄)로 끝난다.
  - 지도 전체 푸시는 파일 하나가 바뀔 때마다 최대 16MiB를 다시 보낸다. 경로만 알리면 뷰어가 필요할 때 한 번 받는다.
- **결과**:
  - 파서 단위 테스트 48개. 픽스처 읽기, 새 minor의 모르는 필드 버리기, 새·옛 major 거부, 버전 표기 오류, JSON 아님과 지도 아님 구분, 16MiB 초과(한글 600만 자처럼 UTF-16 길이는 상한 아래지만 UTF-8로 넘는 경우 포함), 필드 12종의 위치 보고, 단계 트리 7종(최상위 없음, 둘, 없는 노드, 한 노드에 두 단계, 끊어진 순환, 중복 id, `__root__`), `__proto__` 키, RPC 요청·응답·푸시를 본다.
  - 뷰어 변환 테스트 5개, 다국어 테스트 1개, E2E 3개(`tests/open-map.spec.ts`: 랜딩에서 열기와 드릴다운, 거부 뒤 다른 파일 열기, 한국어). 거부 뒤 다시 열기는 휴대폰·태블릿 화면에서도 돈다.
  - 공유·갤러리 뷰어에도 있던 문제를 같이 고쳤다. 스냅샷 모드에서도 캐시된 노드에 다시 분석 버튼이 보였고, 누르면 방문자의 AI 설정으로 분석을 다시 돌렸다. 이제 스냅샷 모드에서는 그 버튼이 없다.
- **재검토 조건**:
  - 닫힌 목록에 값을 더하느라 major가 한 해에 두 번 넘게 오르면, 모르는 값을 `unknown`으로 읽는 방식(i)을 다시 본다.
  - T2-3 검증기나 에이전트가 파일에서 심볼이나 코드 관계를 읽어야 하면 `symbols`·`relations`를 minor로 더한다.
  - 실제 지도가 16MiB 상한에 닿으면 상한과 `map.get` 분할을 함께 다시 정한다.
  - 이 타입을 쓰는 쪽이 저장소 밖으로 나가면(별도 저장소의 플러그인 등) 패키지로 뺀다.
