# ADR-20: Markdown 개요를 코드 구조 요약에 넣고, 포함 경로가 제외 규칙보다 우선

- **날짜**: 2026-11-10
- **문제**: 에이전트 스킬·지침 저장소는 `SKILL.md`, `AGENTS.md`, 규칙 파일 같은 Markdown이 본체다. 그런데 Markdown은 파싱 대상이 아니어서 심볼이 0개가 되고 코드 구조 요약에서 빠졌다. 지침 폴더(`.agents`, `.claude`, `.cursor`, `.github/instructions` 등)는 숨김 폴더 규칙으로 불러오기 단계에서 빠졌다. `.mjs`·`.cjs`도 언어 목록에 없었다. 같은 규칙으로 두 저장소를 재 보니 AI에 가는 파일이 jakubkrehel/skills는 104개 중 최대 9개, tt-a1i/archify는 1,189개 중 최대 29개였고 Markdown은 0개였다
- **검토 대안**:
  - (A) Markdown 본문을 잘라 보낸다 — 맥락은 가장 많지만 "소스 코드 원문은 밖으로 나가지 않는다"는 약속과 충돌한다. 본문과 코드 블록에 실제 코드나 키 예시가 들어 있는 경우가 있다
  - (B) 제목은 H1~H3만 — 크기는 작지만 스킬 문서는 H4 이하에 "언제 쓰나", "하지 말 것" 같은 규칙을 두는 경우가 있어 잘린다
  - (C) frontmatter의 `name`·`description`, H1~H6 제목(단계대로 중첩), 저장소 안 파일로 가는 링크만 보낸다. 본문 문단과 코드 블록은 읽지 않는다
  - 지침 폴더: (D) 숨김 폴더 규칙을 끈다 — `.git` 밖의 캐시·작업 트리(`.claude/worktrees` 등)까지 들어온다. (E) 알려진 지침 위치를 기본 포함 목록으로 두고, 사용자가 포함 목록을 더할 수 있게 한다. 포함은 제외(기본 목록, 사용자 제외 목록, 숨김 규칙, 코드 구조 요약의 제외 경로)보다 우선한다
- **결정**: C와 E. Markdown 개요는 tree-sitter 없이 메인 스레드에서 뽑는다(`markdownOutline.ts`). 개요 항목은 심볼 종류 `frontmatter`·`heading`으로, 링크는 `import`로 넣어 기존 코드 구조 요약 형식을 그대로 쓴다. 포함 항목은 이름만 쓰면 어느 깊이든, `/`가 들어가면 루트부터의 경로로 맞춘다. 약속 문구는 "소스 코드 원문"으로 둔다(앱 안내문은 이미 이 표현이다)
- **기각 이유**: A는 약속을 바꿔야 한다. B는 측정한 두 저장소에서 H4 이하가 각각 0개, 9개라 아끼는 크기가 거의 없다. D는 불필요한 파일과 다른 작업 트리의 복사본을 읽는다
- **결과**: 같은 두 저장소에서 AI에 가는 파일이 jakubkrehel/skills 83개(Markdown 64, `SKILL.md` 15개 전부), tt-a1i/archify 271개(Markdown 132, `SKILL.md` 5개 전부, 코드 최대 139). 요약 크기는 각각 43.8KB, 148.7KB로 기본 한도 250KB 안이다. 코드 파일은 심볼이 1개 이상 나온다고 가정한 상한이다.
- **보내는 범위의 세부**: frontmatter `description`은 문장이므로 최대 500자까지 그대로 간다. 제목 글자도 그대로 간다. 코드 블록(울타리), HTML 주석, 2,000자를 넘는 줄은 읽지 않는다. 4칸 들여쓰기 코드 블록 안의 링크 대상(경로)은 거를 수 없어 import로 갈 수 있다
- **우선순위**: 일반 Markdown(문서, 변경 기록)도 개요를 뽑지만 불러오기와 요약 예산에서 맨 뒤로 보낸다. `SKILL.md`, `AGENTS.md`, `CLAUDE.md`, `GEMINI.md`, `README.md`, `.mdc`, 포함 경로 안의 파일은 제자리를 지킨다
- **성능**: Markdown 개요는 메인 스레드에서 돈다. 패턴은 줄마다 선형이 되게 만들었다(긴 줄 4만 자에서 100ms 안, 테스트로 고정)
- **재검토 조건**: 지침 파일 위치가 크게 바뀌거나(새 에이전트, 표준 경로 변경) 개요만으로 역할 구분이 틀린다는 사례가 나오면 다시 본다. Markdown 본문 요약이 필요하다는 판단이 서면 A를 사용자가 켜는 선택지로 검토한다
