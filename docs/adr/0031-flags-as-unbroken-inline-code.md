# ADR-31: 문구 속 명령줄 플래그는 백틱으로 표시하고 줄바꿈 없는 코드로 그린다

- **날짜**: 2026-11-17
- **문제**: `/bridge` 연결 카드의 `--cli gemini`가 하이픈에서 줄이 바뀌어 `-`와 `-cli gemini`로 갈라졌다. 브라우저는 하이픈 뒤를 줄바꿈 자리로 본다. 같은 일이 `--token`, `--root`, `~/.ropeman/bridge-token` 같은 플래그와 경로를 담은 i18n 문구, 그리고 문서의 인라인 코드에서 390px 폭으로 났다. 문서는 `getting-started`, `bridge-setup`, `faq`에서 하이픈 뒤 줄바꿈 31곳을 쟀다(두 언어 합).
- **검토 대안**:
  - (A) 문구의 하이픈을 줄바꿈 없는 하이픈(U+2011)이나 단어 결합자(U+2060)로 바꾼다. 화면은 맞지만 사용자가 복사한 명령에 보이지 않는 문자가 들어가 셸에서 실패한다.
  - (B) `AgentSetup`처럼 문구를 자리표시자 앞뒤 두 키로 나눈다. 한 문장에 플래그가 셋까지 있어 키가 문장마다 여러 개로 늘고, 어순이 다른 한국어와 영어가 같은 조각 수를 맞춰야 한다.
  - (C) 문구 안에서 백틱으로 코드 부분을 표시하고, 컴포넌트 하나가 백틱 쌍을 `<code>`로 그린다. `<code>`는 `white-space: nowrap`이다.
  - (D) CSS만으로 막는다. 하이픈 뒤 줄바꿈만 막는 속성은 없고, 인라인 코드 전체에 `nowrap`을 주면 긴 URL이 폰 화면 밖으로 나간다.
- **결정**: i18n 문구는 (C), 문서는 같은 생각을 mdsvex 단계에 적용한다.
  - `utils/inlineCode.ts`의 `splitInlineCode`가 문구를 `{ text, code }` 조각 목록으로 나누고, `InlineCodeText.svelte`가 그 목록을 그린다. 짝이 없는 백틱은 글자로 남는다. `{@html}`을 쓰지 않으므로 문구에 든 값이 HTML로 해석되지 않는다.
  - 문서는 `scripts/rehype-inline-code.mjs`가 인라인 코드(`pre` 밖의 `code`)를 공백에서 나누고, 하이픈이 든 32자 이하 단어를 `code-word` 스팬으로 감싼다. 문서 페이지가 이 스팬에 `nowrap`을 준다. 공백은 그대로 줄바꿈 자리이고, 긴 URL은 전처럼 줄이 바뀐다. 복사한 글자는 바뀌지 않는다.
  - `i18nStore.test.ts`가 문구마다 백틱 짝이 맞는지, 백틱 밖에 `--플래그`가 없는지, 한국어와 영어의 코드 조각이 같은지 본다.
- **결과**:
  - 프로덕션 빌드(`wrangler pages dev`)에서 `/bridge`를 1180px와 390px, 두 테마로 열었을 때 두 줄에 걸친 코드 조각이 없었다. 문서 6쪽을 두 언어로 390px에서 열었을 때 하이픈 뒤 줄바꿈이 31곳에서 0곳이 됐고, 가로 넘침은 0px였다(2026-11-17).
  - 백틱으로 표시한 문구를 `InlineCodeText` 없이 그리면 백틱이 글자로 보인다. 그래서 그런 문구는 모두 이 컴포넌트로 그린다. 지금은 `landing.featureDrillDesc`, `bridgeAccess.refusedHint`, `bridge.desc`, `bridge.tokenHint`, `bridge.namingNoCli`, `bridge.noRoot`다.
- **재검토 조건**:
  - 굵게나 링크처럼 문구 안에 다른 표시가 필요해지면, 백틱 하나만 읽는 이 형식 대신 작은 마크업 규칙을 정한다.
  - 문서의 인라인 코드에 32자보다 긴 플래그가 생겨 하이픈에서 갈라지면 길이 한도를 다시 정한다.
