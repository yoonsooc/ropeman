# ADR-25: 맥락은 사용자의 에이전트가 쥐고, 깊은 폴더는 일꾼이 동시에 이름 붙인다

- **날짜**: 2026-11-13
- **상태**: 확정. 사용자가 2026-11-13에 정했다(전략 문서 A-8 개정). 같은 날 세 번 바뀌었다(아래 "결정 과정"). 전달 경로(Bridge, 로컬 모드, JSON 열기)는 ADR-23 그대로다
- **문제**: T2-4의 serve는 사용자가 폴더를 열 때마다 `claude -p`나 `gemini`를 새로 띄워 이름을 붙였다. 새로 뜬 CLI는 사용자가 에이전트와 나눈 대화를 모른다. 스킬(T2-6)은 사용자가 이미 대화하고 있는 에이전트(MAIN) 안에서 돈다. MAIN이 모든 클릭을 직접 처리하면 맥락은 이어지지만 MAIN이 병목이 되고, 그동안 사용자는 대화를 쓸 수 없다. 브라우저 클릭으로 MAIN을 깨울 방법도 호스트마다 다르다.
- **검토 대안**:
  - (A) serve가 클릭마다 헤드리스 CLI를 띄운다(T2-4 그대로). 클릭 즉시, 여러 폴더를 동시에 이름 붙인다. 대신 대화 맥락이 없다.
  - (B) MAIN이 위쪽 단계에 이름을 미리 붙인다. 이름은 파일(`names.json`)에 쓰고, `ropeman map`이 검증해 통과한 단계만 `ropeman.json`에 넣는다. 더 깊이 누른 폴더는 serve가 대기열(`queue.json`)에 쌓고, MAIN이 다음 대화 때 처리한다.
  - (C) B에 더해, MAIN이 `ropeman next`로 클릭을 기다린다("브라우저 따라 탐색"). 셸 명령 하나라 어느 에이전트에서나 돈다. 기다리는 동안 그 대화는 다른 일을 못 한다.
  - (D) Claude Code 채널(MCP 서버가 돌고 있는 세션에 이벤트를 넣는 기능, 연구 미리보기). Claude Code에서만 되고 미리보기다.
  - (E) MCP 도구만 둔다. 서버는 에이전트를 깨우지 못하므로 결국 C처럼 에이전트가 물어봐야 한다.
  - (F) B와 A를 합친다. MAIN은 위쪽 단계에 이름을 붙이고 맥락 요약(`brief.md`)을 쓴다. 깊은 클릭은 일꾼(헤드리스 CLI)이 요약과 위 단계 이름을 받아 동시에 이름 붙이고, 결과를 기록에 남긴다. MAIN은 다음 대화 때 기록을 읽는다. 일꾼이 없으면 B의 대기열로 간다.
- **결정**: F. gemini 일꾼은 `--cli gemini`로 직접 고를 때만 쓴다. C는 넣지 않는다. D는 나중에 "MAIN에게 바로 알리기"로만 본다.
  - 작업 폴더(`--out`)의 파일은 쓰는 쪽이 하나씩이다. MAIN은 `names.json`과 `brief.md`, `ropeman map`은 `ropeman.json`과 `work.json`, serve는 `queue.json`과 `naming-log.jsonl`, `ropeman inbox`는 `inbox-read.json`(기록을 어디까지 읽었나)만 쓴다. 그래서 잠금이 필요 없고, 채널(D)도 같은 파일을 쓰면 된다(`bridge/src/workFolder.ts`).
  - `names.json`은 노드 id마다 `label`, `description`, `keySymbols`다. 일꾼에게 묻는 필드와 같고 검사도 같은 함수(`parseNamingAnswer`, `applyNames`, `verifyMap`)다. 한 단계는 부분 전부에 이름이 있고 검증기를 통과할 때만 이름이 붙는다. 나머지 단계는 폴더 이름(`grouped`)으로 남아서 `ropeman.json`은 늘 검증기를 통과한다. 문제 코드는 검증기의 17개에 `names-unreadable`, `node-unknown`, `name-missing`, `name-invalid`, `map-invalid`를 더했다.
  - 단계는 깊이다. 1단계가 최상위, 2단계가 그 안의 폴더이고 기본은 2단계까지다(`--depth`).
  - `brief.md`: 사용자 의도, 용어, 이름 규칙, 위 단계 이름. 비밀 값은 넣지 않는다고 스킬이 적는다. 의도가 바뀌면 MAIN이 다시 쓴다. serve는 앞의 4,000바이트만 프롬프트에 넣고 잘랐다고 적는다.
  - 일꾼: `--cli`가 없으면 `claude`만 찾는다. 프롬프트에는 구조(경로, 선언 이름, import 수), 요약, 그 폴더가 위 단계에서 받은 이름이 들어간다. 파일 내용은 넣지 않는다. 동시 실행은 serve 전체에서 2개다. 검증을 통과한 이름은 `node.named`로 바로 보내고, `namedBy`(일꾼 이름, 이번 세션의 일꾼 실행 수)를 함께 보낸다. 선택 필드라 스키마는 1.1이다(ADR-24의 minor 규칙). 뷰어는 어느 일꾼이 이름을 붙였는지와 실행 수를 보여 준다. 결과(노드, 폴더, 이름, 일꾼, 시각, 걸린 시간)는 성공과 실패 모두 `naming-log.jsonl`에 한 줄씩 붙인다.
  - `ropeman inbox`: 아직 아무도 이름 붙이지 않은 대기열 폴더와, 지난번 이후 기록에 붙은 일꾼 결과를 한 번에 돌려준다. 스킬은 이후 메시지마다 이것을 먼저 돌리게 한다. MAIN은 사용자가 무엇을 열어 봤는지 알고, 이름을 고쳐 달라는 요청에는 그 결과를 `names.json`에 옮겨 고친 뒤 `ropeman map`으로 검증한다. serve는 바뀐 `ropeman.json`을 다시 읽어 화면에 보낸다.
  - 갈림은 `server.ts`의 `namingCli` 한 곳이다. 일꾼이 있으면 일꾼, 없고 `--out`이 있으면 대기열, 둘 다 없으면 폴더 이름 그대로다. 대기열은 `node.named`에 `code: "queued"`로 알린다. 푸시 코드는 ADR-24의 열린 목록이라(옛 뷰어는 `unknown`으로 읽고 문장을 보여 준다) major를 올리지 않는다.
  - 작업 폴더는 클론한 저장소가 채워 올 수 있다. 그래서 그 안의 파일은 링크를 따라가지 않고 일반 파일만 상한까지 읽고, 링크인 `--out`은 거부한다. 저장소 안의 작업 폴더에는 `*` 한 줄짜리 `.gitignore`를 넣는다. 기본 `--out`을 저장소 밖으로 옮기는 안은 저장소 안을 고른 경우를 막지 못해 고르지 않았다.
  - 기록은 1,000,000바이트 아래로 잘라 둔다. `ropeman inbox`는 줄 수가 아니라 줄마다 붙은 `seq`(늘기만 하는 번호)로 어디까지 읽었는지 기억해서, 자르기나 serve 재시작 뒤에도 같은 줄을 두 번 보이거나 새 줄을 빠뜨리지 않는다. 일꾼이 도는 동안 MAIN이 그 폴더 이름을 쓰면 MAIN 이름이 이긴다.
  - serve는 검증에 한 번 실패한 이름을 지우지 않고 그 추출에서만 거부한다. 대기열에서 이름이 생긴 폴더와 지도에서 사라진 폴더는 추출할 때마다 뺀다.
- **결정 과정** (2026-11-13): 처음에는 B와 C를 정하고 헤드리스를 `--cli`로만 돌게 했다. 사용자가 여러 클릭을 동시에 이름 붙이는 것을 중요하게 봐서 C와 헤드리스 끄기를 보류했다. 마지막으로 F를 골랐다. 만들었던 `ropeman next`는 지웠다.
- **기각 이유**:
  - A만 쓰면 대화 맥락이 끊긴다. F는 요약과 위 단계 이름으로 그 맥락을 일꾼에게 넘긴다.
  - B만 쓰면 MAIN이 모든 깊은 클릭의 병목이 되고, 사용자는 다음 대화까지 이름을 기다린다.
  - C는 기다리는 동안 사용자가 대화를 못 쓴다.
  - D는 Claude Code에서만 되고 미리보기다. E는 서버가 에이전트를 깨우지 못해 C보다 나은 점이 없다.
  - gemini 자동 선택: 래퍼가 gemini를 헤드리스로 부르는 것이 허용되는지 정책이 불분명하고, 계정이 정지된 전례가 있다.
  - MAIN이 `ropeman.json`을 직접 고치는 방식: PASEO 지도는 5MB라 고치기 어렵고, 노드 파일 목록을 잘못 바꾸면 이름이 아니라 구조가 깨진다.
- **결과**: PASEO 실측은 `docs/ARCH.md`의 "스킬과 작업 폴더" 절에 있다.
- **재검토 조건**: 채널이 정식이 되거나 다른 에이전트에도 비슷한 기능이 생기면 "MAIN에게 바로 알리기"를 더한다. 일꾼 이름이 요약을 따르지 않는다는 불만이 많으면 요약 형식이나 일꾼 프롬프트를 다시 본다. gemini 정책이 분명해지면 자동 선택을 다시 본다.
