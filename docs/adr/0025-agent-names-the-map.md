# ADR-25: 지도의 이름은 사용자가 대화 중인 에이전트가 붙인다

- **날짜**: 2026-11-13
- **상태**: 확정. 사용자가 2026-11-13에 정했다(전략 문서 A-8 개정). ADR-23의 "노드를 누르면 로컬 CLI가 이름을 붙인다"를 이 결정이 대신한다. 전달 경로(Bridge, 로컬 모드, JSON 열기)는 ADR-23 그대로다
- **문제**: T2-4의 serve는 사용자가 폴더를 열 때마다 `claude -p`나 `gemini`를 새로 띄워 이름을 붙였다. 새로 뜬 CLI는 사용자가 에이전트와 나눈 대화를 모른다. 스킬(T2-6)은 사용자가 이미 대화하고 있는 에이전트 안에서 돈다. 그 에이전트가 이름을 붙이면 맥락이 이어지고, 중첩 CLI 실행도 필요 없다. 다만 브라우저에서 깊은 폴더를 누르는 순간 그 에이전트를 깨울 방법은 호스트마다 다르다.
- **검토 대안**:
  - (A) serve가 클릭마다 헤드리스 CLI를 띄운다(T2-4 그대로). 클릭 즉시 이름이 온다. 대신 대화 맥락이 없고, claude나 gemini가 설치돼 있어야 하며, 스킬을 돌린 에이전트가 Codex나 Cursor면 다른 회사의 CLI가 따로 돈다.
  - (B) 스킬을 돌린 에이전트가 위쪽 단계에 이름을 미리 붙인다. 이름은 파일(`names.json`)에 쓰고, `ropeman map`이 검증해 통과한 단계만 `ropeman.json`에 넣는다. 더 깊이 누른 폴더는 serve가 대기열(`queue.json`)에 쌓고, 에이전트가 다음 대화 때 처리한다.
  - (C) B에 더해, 사용자가 원하면 에이전트가 `ropeman next`로 클릭을 기다린다("브라우저 따라 탐색"). 셸 명령 하나라 어느 에이전트에서나 돈다. 기다리는 동안 그 대화는 다른 일을 못 한다.
  - (D) Claude Code 채널(MCP 서버가 돌고 있는 세션에 이벤트를 넣는 기능, 연구 미리보기). 대화를 막지 않고 클릭을 넘길 수 있다. Claude Code에서만 되고 미리보기 단계다.
  - (E) MCP 도구만 둔다. 서버는 에이전트를 깨우지 못하므로 결국 C처럼 에이전트가 물어봐야 한다.
- **결정**: B를 기본으로, C를 사용자가 켜는 선택으로 둔다. A는 `--cli`를 직접 줄 때만 돈다. D는 다음 작업이다.
  - 작업 폴더(`--out`)의 파일은 쓰는 쪽이 하나씩이다. 에이전트는 `names.json`, `ropeman map`은 `ropeman.json`과 `work.json`, serve는 `queue.json`만 쓴다. 그래서 잠금이 필요 없고, 채널(D)도 같은 파일을 읽고 쓰면 된다(`bridge/src/workFolder.ts`).
  - `names.json`은 노드 id마다 `label`, `description`, `keySymbols`다. serve가 CLI에 묻던 필드와 같고, 검사도 같은 함수(`parseNamingAnswer`, `applyNames`, `verifyMap`)를 쓴다. 한 단계는 부분 전부에 이름이 있고 검증기를 통과할 때만 이름이 붙는다. 나머지 단계는 폴더 이름(`grouped`)으로 남아서 `ropeman.json`은 늘 검증기를 통과한다.
  - 문제는 JSON으로 돌려준다. 코드는 검증기의 17개에 `names-unreadable`, `node-unknown`, `name-missing`, `name-invalid`, `map-invalid`를 더했다. 스킬은 코드마다 고치는 방법을 표로 둔다.
  - 단계는 깊이다. 1단계가 최상위, 2단계가 그 안의 폴더이고 기본은 2단계까지다(`--depth`). `work.json`에는 아직 이름이 없는 가장 얕은 단계와 대기열의 폴더만 나온다. 부분마다 파일 수, 경로 12개, 선언한 이름 24개까지이고 파일 내용은 없다.
  - serve는 `--out/ropeman.json`이 바뀌면 다시 읽는다. 대기열에서 이름이 생긴 폴더는 기다리던 화면에 `node.named`로 보내고, 다른 단계가 바뀌었으면 `map.changed`(경로 없음)를 보낸다. 대기열에 넣을 때는 `node.named`에 새 코드 `queued`를 보내고, 뷰어는 "다음 대화 때 에이전트가 이름을 붙인다"고 보여 준다. RPC 오류 코드는 열린 목록이라(ADR-24) 스키마 major는 그대로다.
  - 헤드리스 CLI 코드는 지우지 않는다. 지울지는 사용자가 따로 정한다.
- **기각 이유**:
  - A를 기본으로 두면 대화 맥락이 끊기고, 스킬을 돌린 에이전트와 다른 모델이 이름을 붙인다.
  - C를 기본으로 두면 스킬을 쓰는 동안 사용자가 대화를 못 쓴다.
  - D는 Claude Code에서만 되고 미리보기라, 모든 에이전트에서 도는 B·C를 먼저 둔다.
  - E는 서버가 에이전트를 깨우지 못해 C보다 나은 점이 없고 호스트마다 MCP 설정이 필요하다.
  - 에이전트가 `ropeman.json`을 직접 고치는 방식도 봤다. PASEO 지도는 5MB라 고치기 어렵고, 노드 파일 목록을 실수로 바꾸면 이름이 아니라 구조가 깨진다.
- **결과**: PASEO 실측은 `docs/ARCH.md`의 "스킬과 작업 폴더" 절에 있다.
- **재검토 조건**: 채널이 정식이 되거나 다른 에이전트에도 비슷한 기능이 생기면 C를 그쪽으로 옮긴다. 사용자가 대기열을 거의 쓰지 않거나 이름을 기다리는 시간이 불만이면 A를 다시 본다.
